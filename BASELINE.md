## Локальный benchmark без TCP и облака

Одноразовый изолированный процесс .venv: загрузка Vosk Model(model_ru), KaldiRecognizer(16000), 1 s нулевого PCM; затем torch.set_num_threads(4), PackageImporter(v4_ru.pt).load_pickle('tts_models','model'), CPU, aidar/24000, apply_tts для двух фиксированных русских текстов по два раза подряд. Время — time.perf_counter; аудио не воспроизводилось и на ESP не отправлялось. Тексты/точное число samples сохранены в JSON. Нет отдельного warmup; прогон 1 первого текста включает первый вызов модели, последующие уже после него. Это малый диагностический sample, не среднее и не latency SLA. RTF = synthesis_seconds / (samples/24000). Для повторения применять ровно эти тексты, порядок и параметры в новом процессе .venv; записать текущую нагрузку/свободную RAM, сравнивать отдельно холодный и последующие вызовы.

Vosk load + recognizer + подача тишины: 0.7082 s (не время распознавания речи). Silero load: 0.6858 s. Выходы finite, mono; звук не прослушан. Процесс одновременно держал Vosk и Silero. Итоговый RSS 745.8 MiB, peak working set 748.7 MiB, private около 1.52 GiB; это процесс диагностического запуска, не работающий сервер с историей/облаком и не system-wide peak RAM.

## Доступный сквозной baseline

| Метрика | Подтверждённое значение / доступность |
| --- | --- |
| STT / LLM длительность | Чисел в переданном описании нет. В Python есть строки «РАСПОЗНАНО за …» / «LLM ОТВЕТ за …». |
| TTS в рабочем ответе | Числа не предоставлены. Строка «Синтез занял» охватывает подготовку всего PCM до START. Локальный замер выше не заменяет её. |
| TCP-передача | Числа не предоставлены. «Передача заняла» печатается до finish_playback: включая pacing и send, без ACK wait. Не wire-only throughput. |
| ACK wait | Из timestamp Python «Отправка СТОП» до PLAYBACK DONE того же ответа; включает EOS send/диспетчеризацию. Числа отсутствуют. Предел 10 s — настройка, не измерение. |
| Отмена | CANCEL REQUESTED → PLAYBACK CANCELLED по Python; только подтверждённый success, не fallback. Числа отсутствуют. 2 s watchdog — предел, не фактическая latency; до START cooperative model call может ждать дольше. |
| Первый звук / конец | Физическое время не измерено. START не равен первому звуку, DONE — программное подтверждение drain, не акустический датчик. |
| Последний короткий ответ | Python DONE / ESP ACK 00000001 подтверждены пользователем. |
| Последний длинный ответ | Python CANCELLED / ESP CANCELLED 00000002, возврат к ожиданию подтверждены. Полное воспроизведение без отмены не проверено. |
| ESP heap / I2S | Около 220 КБ / ошибок I2S нет по сообщению пользователя. |
| Playback queue / pressure | high 16384/16384, pressure достиг 1194; это backpressure, не доказательство потери PCM. |
| mic_drop | 227 к моменту подключения, далее без роста по сообщению пользователя. Единица — неудачный enqueue блока, не samples/bytes. Причина начального значения не установлена. |

`mic_drops` в текущем C увеличивается только при mic_connected/current generation и неудаче xRingbufferSend (10 ms). Disconnected/stale samples отбрасываются намеренно без увеличения. Счётчик накопительный с загрузки устройства, reconnect его не обнуляет. Поэтому фразу «до TCP» нельзя объяснять обычным disconnected drop: нужны boot-to-connect лог, сведения о ранее успешном соединении и подтверждение версии binary. Код в 1.9 не менялся.

`pressure` увеличивается при каждой неудачной попытке enqueue playback в полную очередь; TCP staging удерживает этот PCM и повторяет. Это число попыток/событий, не уникальных блоков или потерянных байт. high — максимум программной очереди, full ≈341 ms при 48 KB/s PCM, без DMA/сокетных буферов; normal pressure не доказывает underrun. empty включает нормальный конец и не равен слышимому обрыву. i2s_bytes означает принято драйвером, не физически сыграно. Статистика накопительная, анализировать дельты внутри одного boot, границы reconnect/Reset указывать явно.

## Незавершённый текст и секреты

Длинный ответ LLM про котиков закончился незавершённым предложением уже в логе LLM. Причина не установлена: существующий max_tokens=500 — возможное объяснение, но finish_reason/usage того вызова отсутствуют. Это не доказательство ошибки дробления TTS или TCP. Генерация/лимиты/модели не менялись. При повторении сохранить полный ответ и доступные finish_reason/usage из результата, не увеличивать лимит автоматически.

Raw логов последнего пользовательского прогона в рабочей папке не найдено; приведённые результаты взяты из сообщения пользователя. Нельзя выполнить полную проверку отсутствия секретов в непредоставленных логах. Новые JSON/документ не содержат значений API/Wi-Fi ключей; environment variables и исходники в снимок не копировались. Активные исходники по-прежнему содержат hardcoded секреты. Текущий код логирует текст речи/ответа и ошибки; приватность содержимого и возможное содержимое SDK ошибок учитывать перед передачей логов. Перенос/ротацию секретов согласовать отдельной задачей; этой задачей они не выполнялись.
