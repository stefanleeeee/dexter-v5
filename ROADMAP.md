## Как принимать задачи

Каждая строка — небольшая задача с результатом и проверкой. Изменять ограниченный участок, сохранять пользовательские правки и рабочий Silero, записывать выполненные тесты и их ограничения. Сначала offline проверки без моделей/облака, затем разрешённые интеграционные и аппаратные тесты. Отчёт «прошло статический просмотр» не заменяет тест. Численные требования к задержкам/ресурсам выбрать по базовым измерениям и согласовать, не выдавать планы за результат.

## Этап 1 — стабилизация существующего Dexter

Цель: надёжная сессия и воспроизводимый голосовой цикл с текущим Silero. Выполнена доступная локальная часть 1.9, зафиксирован baseline и точный сценарий оставшейся аппаратной приёмки. До закрытия сквозных измерений и открытых сценариев не считать этап 1 полностью принятым; к этапу 2 автоматически не переходить.

| Задача | Конкретный результат | Способ проверки |
| --- | --- | --- |
| 1.1 Исправить переходы COMMAND/PROCESSING | Один worker только для завершённой допустимой команды; короткая команда явно сбрасывается; остаток stream_buffer не возвращает PROCESSING в WAKE_WORD | Подставные worker/socket: незавершённая команда — 0 запусков, завершённая — ровно 1, короткая — 0; несколько кадров в одном payload и вход во время PROCESSING не запускают новую сессию. Без импорта моделей и сетевых API |
| 1.2 Определить владельцев состояния и TCP writer | Единственный управляемый отправитель на соединение; lifecycle worker, disconnect и поколение соединения; исключить пересечение временных файлов и вызовов общей модели | Искусственно задержанные два запроса, исключения STT/LLM/TTS и disconnect: парсер видит целые кадры, новая сессия не принимает результат старой; нет конфликтующих WAV |
| 1.3 Исправить ESP send и ошибки приёма | Полная отправка заголовка/тела; malloc/I2S ошибки приводят к определённому восстановлению; проверка длины и чётности | Fault injection коротких send, нуля/ошибки, malloc failure, нечётных/слишком больших payload; отсутствие продолжения разбора из середины PCM. Проверка сборки ESP-IDF и затем устройства |
| 1.4 Сделать reconnect и timeouts определёнными | Срок приёма тела/отправки, очистка устаревшего mic audio, явное состояние connected | Обрыв заголовка/тела, зависший peer, отключение Wi-Fi, повторное соединение: восстановление за установленный deadline, без старого аудио и утечек |
| 1.5 Развязать сеть и I2S | Ограниченная очередь playback и отдельный consumer; TCP приём/отправка микрофона не ждут долгого I2S write; политика overflow/underrun | На устройстве длительное воспроизведение при uplink: счётчики потерь, queue depth, heap, непрерывность PCM; очередь ограничена и задачи не зависают |
| 1.6 Ввести завершение воспроизведения | Согласованная спецификация EOS и ACK после выдачи последнего звука; обе стороны обновлены совместно | Поддельный consumer различает send complete и playback complete; на плате ACK не раньше конца I2S, timeout ACK обрабатывается. Старые 0x11/0x13 сами по себе этого не обеспечивают |
| 1.7 Определить основу отмены (реализовано; отмены подтверждены, Reset открыт) | Поколение/session ID, сброс очереди, запрет воспроизведения устаревших блоков; отдельный локальный/тестовый сигнал отмены | Отмена во время STT, TTS, send и playback; старая сессия не оживает. Это ещё не голосовой barge-in: он остаётся этапу 3 |
| 1.8 Исправить граничные PCM случаи (реализовано; 136 тестов, прослушивание ожидается) | Пик считается в широком типе; безопасный clipping TTS; согласованные форматы без молчаливой обрезки текста | PCM с -32768, тишина, насыщенный сигнал, текст >900 символов, пустой ответ: ожидаемый диапазон и отсутствие потерянного текста |
| 1.9 Зафиксировать базовый запуск и метрики (локальная часть выполнена; сквозная приёмка открыта) | Описать фактическое окружение без массовой переустановки, cwd/пути, недостающие декларации зависимостей; отдельно согласовать хранение секретов | Разрешённый запуск Vosk/Silero и сквозной аппаратный цикл, серия коротких/длинных запросов, повторные подключения. Критерий выхода: 1.1–1.9 приняты с записанными результатами, Silero сохранён; обычные и ошибочные сценарии не создают пересекающиеся сессии и повреждённые TCP-кадры.
