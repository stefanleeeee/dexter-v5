## Как принимать задачи

Каждая строка — небольшая задача с результатом и проверкой. Изменять ограниченный участок, сохранять пользовательские правки и рабочий Silero, записывать выполненные тесты и их ограничения. Сначала offline проверки без моделей/облака, затем разрешённые интеграционные и аппаратные тесты. Отчёт «прошло статический просмотр» не заменяет тест. Численные требования к задержкам/ресурсам выбрать по базовым измерениям и согласовать, не выдавать планы за результат.

## Этап 1 — стабилизация существующего Dexter

Цель: надёжная сессия и воспроизводимый голосовой цикл с текущим Silero. Выполнена доступная локальная часть 1.9, зафиксирован baseline и точный сценарий оставшейся аппаратной приёмки. До закрытия сквозных измерений и открытых сценариев не считать этап 1 полностью принятым; к этапу 2 автоматически не переходить.

| Задача | Конкретный результат | Способ проверки |
| --- | --- | --- |
| 1.1 Исправить переходы COMMAND/PROCESSING | Один worker только для завершённой допустимой команды; короткая команда явно сбрасывается; остаток stream_buffer не возвращает PROCESSING в WAKE_WORD | Подставные worker/socket: незавершённая команда — 0 запусков, завершённая — ровно 1, короткая — 0; несколько кадров в одном payload и вход во время PROCESSING не запускают новую сессию. Без импорта моделей и сетевых API |
| 1.2 Определить владельцев состояния и TCP writer | Единственный управляемый отправитель на соединение; lifecycle worker, disconnect и поколение соединения; исключить пересечение временных файлов и вызовов общей модели | Искусственно задержанные два запроса, исключения STT/LLM/TTS и disconnect: парсер видит целые кадры, новая сессия не принимает результат старой; нет конфликтующих WAV |
| 1.3 Исправить ESP send и ошибки приёма | Полная отправка заголовка/тела; malloc/I2S ошибки приводят к определённому восстановлению; проверка длины и чётности | Fault injection коротких send, нуля/ошибки, malloc failure, нечётных/слишком больших payload; отсутствие продолжения разбора из середины PCM. Проверка сборки ESP-IDF и затем устройства |
| 1.4 Сделать reconnect и timeouts определёнными | Срок приёма тела/отправки, очистка устаревшего mic audio, явное состояние connected | Обрыв заголовка/тела, зависший peer, отключение Wi-Fi, повторное соединение: восстановление за установленный deadline, без старого аудио и утечек |
| 1.5 Развязать сеть и I2S | Ограниченная очередь playback и отдельный consumer; TCP приём/отправка микрофона не ждут долгого I2S write; политика overflow/underrun | На устройстве длительное воспроизведение при uplink: счётчики потерь, queue depth, heap, непрерывность PCM; очередь ограничена и задачи не зависают |
| 1.6 Ввести завершение воспроизведения | Согласованная спецификация EOS и ACK после выдачи последнего звука; обе стороны обновлены совместно | Поддельный consumer различает send complete и playback complete; на плате ACK не раньше конца I2S, timeout ACK обрабатывается. Старые 0x11/0x13 сами по себе этого не обеспечивают |
| 1.7 Определить основу отмены (реализовано; отмены подтверждены, Reset открыт) | Поколение/session ID, сброс очереди, запрет воспроизведения устаревших блоков; отдельный локальный/тестовый сигнал отмены | Отмена во время STT, TTS, send и playback; старая сессия не оживает. Это ещё не голосовой barge-in: он остаётся этапу 3 |
| 1.8 Исправить граничные PCM случаи (реализовано; 136 тестов, прослушивание ожидается) | Пик считается в широком типе; безопасный clipping TTS; согласованные форматы без молчаливой обрезки текста | PCM с -32768, тишина, насыщенный сигнал, текст >900 символов, пустой ответ: ожидаемый диапазон и отсутствие потерянного текста |
| 1.9 Зафиксировать базовый запуск и метрики (локальная часть выполнена; сквозная приёмка открыта) | Описать фактическое окружение без массовой переустановки, cwd/пути, недостающие декларации зависимостей; отдельно согласовать хранение секретов | Разрешённый запуск Vosk/Silero и сквозной аппаратный цикл, серия коротких/длинных запросов, повторные подключения. Измерить первый звук, конец, heap/RAM и потери; проверить отсутствие секретов в логах |

Критерий выхода: 1.1–1.9 приняты с записанными результатами, Silero сохранён; обычные и ошибочные сценарии не создают пересекающиеся сессии и повреждённые TCP-кадры. Звук и reconnect проверены на реальном ESP32; подтверждено фактическое окончание и базовая отмена. Окружение и baseline известны. До этого CosyVoice не подменяет работающий тракт.

## Этап 2 — CosyVoice 3 без streaming

Зависимость: принятый этап 1. Цель: оценить и встроить полный синтез с обратимым выбором TTS.

Кандидат: `FunAudioLLM/Fun-CosyVoice3-0.5B-2512`. На 2026-11-05 [официальная карточка модели](http<local-path>) заявляет русский/английский и потоковые возможности; это сведения поставщика, не результат Dexter. Установку и интерфейс сверять с выбранной ревизией [официального репозитория](http<local-path>). Маркетинговые задержки не считать измерениями ноутбука.

| Задача | Конкретный результат | Способ проверки |
| --- | --- | --- |
| 2.1 Проверить совместимость | Зафиксировать CPU/RAM/GPU/VRAM, ОС, драйверы, ревизию модели и runtime, лицензию; выбрать native Windows либо изолированный поддерживаемый вариант | Сопоставить требования выбранного runtime с оборудованием; описать причины выбора и stop-condition при нехватке ресурсов. Не предполагать обязательный GPU или работоспособность Windows |
| 2.2 Подготовить отдельное окружение | Только после разрешения: изолированная установка и воспроизводимый запуск, без изменения окружения Dexter | Smoke test полного синтеза; версии/ревизии зафиксированы, Silero запускается как прежде, удаление изолированной установки не затрагивает сервер |
| 2.3 Проверить качество | Набор RU, EN, смешанных фраз, чисел, имён, технических терминов, коротких/длинных ответов; несколько разрешённых мужских референсов | Прослушивание и оценка разборчивости, пропусков/повторов, тембра и произношения на одном наборе с Silero; reference.wav не считать автоматически подходящим |

| 2.6 Проверить возврат | Silero доступен настройкой, сбой CosyVoice не оставляет зависшую сессию | Ошибка загрузки, timeout/OOM и выбор Silero: ожидаемое восстановление, понятный лог; повторный аппаратный baseline |

Критерий выхода: полное аудио стабильно звучит на ESP, качество RU/EN/смешанной речи и мужского голоса принято пользователем, ресурсы/задержки измерены и приемлемы, откат к Silero проверен. При несовместимости — документированный результат и сохранение текущего backend; этап 3 не начинается.

## Этап 3 — потоковая генерация CosyVoice 3

Зависимость: успешный этап 2. Цель: снизить задержку первого звука, не потеряв непрерывность и управляемость. Text-in и audio-out проверяются отдельно.

| Задача | Конкретный результат | Способ проверки |
| --- | --- | --- |
| 3.1 Проверить API streaming | Матрица возможностей выбранной версии: генератор текста, чанки аудио, ограничения контекста/референса | Минимальный изолированный пример каждого поддержанного режима. Если text-in недоступен, явно записать ограничение; нарезку готового текста не называть text-in streaming |
| 3.2 Подать текст постепенно | Поддерживаемый text-in и/или безопасная сегментация потока LLM; границы слов/предложений, отмена | Разрывы токенов внутри слова, пунктуации, RU/EN, пустые/ошибочные события: нет потерь и дублей текста. LLM streaming сейчас не реализован, добавляется отдельным изменением |
| 3.3 Выдать поток PCM | Audio-out iterator, сохранение состояния ресемплера между чанками, ограниченная producer/consumer очередь | Сравнить длину/порядок с полным сигналом, проверить диапазон PCM, отсутствие швов и неограниченного роста памяти |
| 3.4 Связать с ESP | Передача чанков <=4096 байт, политика prebuffer и backpressure поверх очереди этапа 1 | Искусственные задержки генерации/сети, медленный consumer: измерить underrun, глубину очереди и первый звук; не подбирать sleep вслепую |
| 3.5 Завершать и прерывать | EOS/ACK и cancel из этапа 1 работают для потока; определить обработку повторного обращения/акустического эха | Прерывание на разных границах блока, задержанные старые блоки, повторный wake word; на плате проверить прекращение звука и начало новой сессии. AEC/barge-in — отдельная проверяемая подзадача, не свойство TCP |
| 3.6 Принять качество потока | Измеренная задержка первого звука и непрерывность, сохранение non-streaming/Silero fallback | Один набор текстов в полном и потоковом режимах, длинный диалог, Wi-Fi jitter и reconnect; прослушивание плюс счётчики, сравнение с этапом 2 |

Критерий выхода: streaming аудио подтверждён на устройстве, text-in статус явно известен, потери/паузы и ресурсы укладываются в согласованные пределы; конец и прерывание корректны, fallback проверен. Значения модели из её описания не подменяют эти измерения.
